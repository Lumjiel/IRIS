## Findings（完整版见下方内联文件；核心结论）

1. **TradingAgents** — 数据层：`tradingagents/dataflows/interface.py` 多 vendor 抽象 + `VENDOR_METHODS`/`TOOLS_CATEGORIES` 注册表 + 配置化 fallback（v0.3.0 起禁止静默回退到未配置供应商）。团队结构：Analyst（4 类）→ Researcher（Bull/Bear 辩论）→ Trader → Risk Team（三风险偏好辩论）→ Fund Manager；核心原创是**结构化报告通信协议**。已验证：论文 3 月回测 ≥23.21% CR / 24.90% AR / 超基线 6.1pp（作者自报，Sharpe 异常高已自曝）；社区实操 $0.05/run。坑（[高]）：Issue #1007 `yfinance_news.py::get_global_news_yfinance()` 未来新闻注入回测（静默前视偏差）；Issue #830 Portfolio Manager 幻觉支撑位；Issue #805 模型级时间泄露。星数核验 ~99k（"~100k"属实）。
2. **FinanceAgent-LangGraph** — 分层策略：`src/decision/rules.py` 确定性 6 级规则引擎 + `src/nodes/supervisor_agent.py` LLM 只叙述不决策（输出强制覆写 + confidence clamp）；GPT-4.1-nano ×9 + mini ×1。17.6s 来自 `benchmark.py` threading 插桩（5×S&P ticker，Gantt 时间线，Supervisor 8.93s≈51% 串行瓶颈）；$0.0018 来自 LangSmith 65 runs trace；README 自注 benchmark 已过时。HITL：`interrupt_before=["trade_gate"]` + PostgresSaver/SqliteSaver + `/approve` 用 `graph.invoke(None, config)` 恢复 + approval_audit 原子幂等 + fail-closed 认证（app.py:209–459 逐行核验）。
3. **LangAlpha PTC** — agent 在 Daytona 沙箱写 Python 处理 MCP 数据，MCP schema 在 workspace init 自动生成类型化模块，prompt 每 server 仅留一行摘要（80 tools，prompt 成本与工具数解耦）。外部印证：Databento MCP 维护者独立复现同一痛点（改 Parquet+DuckDB 查询）、sift-gateway 同构方案。**未验证**[高]：无公开 benchmark（作者 HN 自认 building towards a benchmark）；输出无 validation layer。

## 借鉴速查

- **TradingAgents 最该借**：结构化通信协议、数据层 vendor 抽象 + fallback 注册表。**最不该借**：回测收益数字当卖点、每决策 11 次 LLM 调用管线、无校验的分析师信任链（反向加分：加 verifier agent 回应 Issue #830）。

- **LangAlpha 最该借**：PTC 模式（对比实验：MCP 直灌 vs 沙箱写代码）、schema→typed module 生成、workspace 持久化。**最不该借**：三端全栈大基建、免费数据依赖链、任何盈利叙事。

## 1. TradingAgents（TauricResearch）— 多 Agent 交易公司模拟

### 1.1 数据层怎么做的
- 多供应商抽象：`tradingagents/dataflows/interface.py` 定义统一接口，按供应商分发（alpha_vantage / y_finance），配有 `VENDOR_METHODS`、`TOOLS_CATEGORIES` 注册表与 `route_to_vendor()` 路由、`VendorError` 异常体系。配置化 fallback：某供应商限流/失败时自动切换，保证可用性。
- v0.3.0 起加了"已验证的数据访问契约"——禁止静默回退到未配置的供应商，可选数据类别做优雅降级（`OPTIONAL_CATEGORIES`）。[DeepWiki Data Layer](https://deepwiki.com/TauricResearch/TradingAgents/4-data-layer)、[Extending Data Vendors](https://deepwiki.com/TauricResearch/TradingAgents/9.1-extending-data-vendors)
- 回测数据集是 6 类多模态数据：历史价格、新闻（Bloomberg/Yahoo/EODHD/FinnHub/Reddit）、社交媒体帖+情感分、内幕交易（SEDI/公司 filing）、财务报表、60 个技术指标。[arXiv:2412.20138](https://arxiv.org/html/2412.20138v5)
- 数据层踩坑史（见 1.3）：新闻抓取路径曾把**未来新闻注入历史回测**（前视偏差），是数据层最严重的已证实缺陷。

### 1.2 多 Agent 团队结构
论文定义了 7 类角色，代码/README 演进为 5 个团队、全流程 ReAct：
1. **Analyst Team**：Fundamental / Sentiment / News / Technical 四类分析师并行收集数据；
2. **Researcher Team**：Bull 与 Bear 两个研究员就分析师报告多轮辩论，facilitator 归纳胜出观点；
3. **Trader**（多种风险偏好 trader）：综合报告与历史数据下单；
4. **Risk Management Team**：风险偏好（risk-seeking/neutral/conservative）三方辩论，评估暴露度；
5. **Fund Manager**：最终批准并更新决策。
关键设计（论文明确贡献）：**结构化通信协议**——agent 间传"结构化报告/文档"，只有辩论时才用自然语言；避免"电话游戏"信息损耗。模型分级：gpt-4o-mini/gpt-4o 快模型做检索/转述，o1 深度推理模型做决策、报告（无需 GPU，只吃 API）。[arXiv:2412.20138 v5](https://arxiv.org/html/2412.20138v5)、[README](https://github.com/TauricResearch/TradingAgents)

### 1.3 被验证的价值点 vs 坑

**价值点（有外部佐证的）**
1. **架构落地能力**被社区认证：「Most multi-agent LLM frameworks promise more than they deliver… shipping the kind of clean role decomposition other frameworks describe but rarely implement」。[apidog](https://apidog.com/blog/tradingagents-multi-agent-llm-trading/)
2. **实操成本低**：社区实测一次 SPY 全流程（GPT-4o 基础 + o1 终审）API 花费约 **$0.05**，配置后易用，模型可随意替换。[Andrew Vu 实操记录](https://adv-andrew.github.io/andrewvu.io/posts/tauric-tradingagents-experience/)
3. **论文回测数字**（作者自报，非第三方）：2024-01-01~03-29 三个月模拟，3 个样本股（AAPL/AMZN/GOOGL）至少 23.21% 累计收益、24.90% 年化，超最优基线 6.1 个百分点；AAPL 逆势期实现 >26%。作者诚实披露两点：Sharpe 异常高（超出 2~3 的经验区间，他们人工核验了决策序列）；每次决策需 **11 次 LLM 调用 + 20+ 次工具调用**，这是只回测 3 个月的原因。[arXiv 结果节](https://arxiv.org/html/2412.20138v5)

**坑（GitHub issues 可查证的）**
- **[高] 前视偏差（已证实 bug）**：`tradingagents/dataflows/yfinance_news.py` 的 `get_global_news_yfinance()` 会把未来日期的新闻混入历史回测，且静默不报错；另有 yfinance 日期过滤边界 issue #986/#987/#992/#993。2026-07 的 v0.3.1 才补上 "Alpha Vantage look-ahead filtering" 修复，说明同类问题反复出现。[Issue #1007](https://github.com/TauricResearch/TradingAgents/issues/1007)
- **[高] LLM 幻觉数据**：用户实测 Portfolio Manager 报告引用「$181.30 是历史验证支撑位」，实际当时 Bollinger 下轨约 $200——管线里没有校验 agent。[Issue #830](https://github.com/TauricResearch/TradingAgents/issues/830)
- **[中] 模型级时间泄露**：基座 LLM 训练数据本身可能"知道"回测期行情（temporal knowledge leakage），传统无前视校验覆盖不到。[Issue #805](https://github.com/TauricResearch/TradingAgents/issues/805)
- **[中] 收益声明被社区整体质疑**：3 个月 + 3 只个股 + 高昂调用成本；官方声明"研究用途、非投资建议"。[GhTrends 综述](https://ghtrends.dev/TauricResearch/TradingAgents/)、[NovVista](https://novvista.com/tauricresearch-tradingagents-multi-agent-llm-trading-framework-educational-or-profitable/)
- 星数核验：~99k（98.5k–99.0k，2026-08 快照），任务描述"~100k"属实（Python 仓库第 31 名）。[GitTrend](https://gittrend.io/repo/TauricResearch/TradingAgents)

### 1.4 简历借鉴结论
**最该借**：① **结构化通信协议**（agent 间传结构化报告 + 仅辩论用对话）——论文核心原创点，讲得出"为什么不用长对话，避免电话游戏"；② **数据层 vendor 抽象 + fallback 注册表**（interface.py / VENDOR_METHODS / 数据访问契约）——体现数据工程意识；③ 角色分工 / Bull-Bear 辩论 / 风控委员会的产品叙事。
**最不该借**：① 把 23.21% / Sharpe>3 当卖点——三个月三只股票 + 有前视偏差史，一问就塌；② 每决策日 11 次 LLM 调用 + 20+ 工具调用的管线——成本故事讲不圆；③ 无数据校验的"分析师信任链"——反向操作：在你的项目里**加一个 verifier/校验 agent**（直接回应 Issue #830 的教训），反而成为加分项。

## 2. FinanceAgent-LangGraph（aakarsh31）— 分层 LLM 策略 + HITL 合规门

### 2.1 分层策略是怎么实现的（源码已 clone 核验）
- **确定性规则引擎 + LLM 叙述**：`src/decision/rules.py` 是纯 Python 策略引擎（6 级规则优先级：Tiebreaker→强方向置信→显式 Sell/Buy→估值+宏观 overlay→默认 Hold；crypto 另存 Fear&Greed 框架），零随机性、全部单测可测。`src/nodes/supervisor_agent.py` 中 prompt 明确 "The investment decision has already been made by the policy engine — your job is to write the investment memo explaining it"；LLM 输出被**强制覆写**为策略结论（记录 `llm_recommendation_matched` 遥测日志），置信度被 clamp 到 policy floor（"LLM 可上调、不可下调"）。
- **分层 LLM**：9 个分析 agent 用 GPT-4.1-nano（快），Supervisor 用 GPT-4.1-mini（聪明）——这是 $0.0018/run 的成本来源。
- **并行两波**：`src/graphs/graph_builder.py` 用 LangGraph 超步并行——Wave1（fundamentals/sentiment/risk/technical）→ Wave2（bull/bear/valuation）→ supervisor → trade_gate；crypto 路径 agent 直连 supervisor 防止图悬挂。

### 2.2 17.6s / $0.0018 指标是怎么测的（可复现的方法论）
- **延迟**：仓库自带 `benchmark.py`——用 `threading` + `time.time()` 给 10 个 agent 逐一插桩计时（不含 trade_gate，注释明说 "pure HITL checkpoint, zero compute"），跑 5 只标普 ticker（AAPL/MSFT/NVDA/GOOGL/META，3mo），输出 Gantt ASCII 时间线。结果：avg 17.60s / p50 16.4s / p99 25.3s；**Supervisor 8.93s 占约 51% 总延迟，是设计上不可并行的串行瓶颈**。
- **成本**：README 注明来自 **LangSmith 生产 trace（65 runs）** 的 token 统计（p50 $0.00180、p99 $0.00197），不是 benchmark.py 算的。
- **复现性注意（README 自曝）**：「benchmark numbers were measured before TechnicalAnalyst was added to the Wave 1 parallel group. Re-run python benchmark.py for updated timings.」——数字已过时，作者自己盖章。

### 2.3 Human-in-the-loop 怎么实现（源码逐行核验，app.py:209–459）
- `src/graphs/graph_builder.py: setup_graph()` 用 LangGraph `compile(checkpointer=…, interrupt_before=["trade_gate"])`；trade_gate 是哑节点（lambda state: state），只用于被 interrupt。
- `app.py /analyze`（app.py:209–280）：`graph.invoke({"ticker","timeframe"}, config)` 跑完全管线，在图应挂起在 trade_gate 前，返回 `status: pending_approval` + supervisor 报告 + 中间态 + data_provenance。
- `app.py /approve/{thread_id}`（app.py:~338）：① X-API-Key 认证 fail-closed（未配置时 503、错钥 401）；② 先查 `approval_audit` 表，已 approved/rejected 直接 409（"closes the resume hole"——拒绝过的线程绝不能恢复越门）；③ `graph.invoke(None, config)` 用 checkpoint 恢复执行（生产 PostgresSaver / 本地 SqliteSaver WAL，7 天清理旧 checkpoint）；④ 原子 INSERT 抢占决策（唯一键冲突→409 幂等）；⑤ 记录信号（`evaluation/signal_store.py`，非致命）→⑥ `alpaca_broker/trade_executor.py` 执行纸面单：**仅 High 置信权益**、$500 notional、7% stop-loss、Sell 仅在持仓时执行、全部非致命化（trade 失败不破坏 /approve 响应）。
- 评估闭环：`evaluation/pipeline_signals` 表记录信号时价格 + **policy rule 归因**（逐规则绩效）+ 30 天成熟后 hit-rate vs SPY（`evaluation/eval_job.py`、`db_eval.py`），MODEL_VERSION 版本化信号系列；配套单测 tests/（decision_rules、routing、trade_executor、win_rate、eval_hit）。

### 2.4 被验证的价值点 vs 坑
**价值点**
1. **工程规范是三家里最硬的**：确定性策略防 LLM 乱决策 + 审计表幂等 + 测试套件 + 指标测量脚本化——"验证过什么"这件事本身有代码证据（本报告直接 clone 核验 7+ 个文件）。
2. HITL 全链路（认证→挂起→恢复→幂等→审计→非致命执行）是完整可演示的 LangGraph 生产模式。
3. 设计自知之明：明确标注 Supervisor 是延迟瓶颈、benchmark 数据过时、stop-loss 估算局限。

**坑（无第三方验证，基于代码审查）**
- **[中] 17.6s 不含人工审批时间**：真实"端到端"含 HITL 等待是小时级，README 指标是"机器端到端"，易被误读。
- **[中] 无公开 eval 结果**：30 天 hit-rate vs SPY 是自建机制，仓库没有发布结果数据；无第三方评测、项目小众（价值主张主要靠代码质量自证）。
- **[低] stop-loss 现价取自 yfinance（`alpaca_broker/trade_executor.py`），用估算 qty 而非成交价**，有偏差。
- **[低] 免费数据源脆弱**：yfinance quoteType 判资产类别、RSS 新闻抓取映射，质量无 SLA。

### 2.5 简历借鉴结论
**最该借**：① **"LLM 解释不决策"的确定性规则层**（rules.py + supervisor 覆写 + confidence clamp）——最容易讲清、最抗面试追问；② **benchmark.py 插桩计时方法论**——"延迟/成本指标是这样测的"自带可信度叙事；③ HITL 完整实现（interrupt + checkpointer + 审计幂等 + fail-closed）。
**最不该借**：① 把 17.6s/$0.0018 当硬指标承诺（样本只有 5 tick、README 已自注过期）；② 10-agent 规模照抄（成本/维护）；③ "production-grade" 措辞——对面试官讲 research/demo 级，聊清楚局限，比虚标强。

## 3. LangAlpha（ginlix-ai）— Programmatic Tool Calling（PTC）模式

### 3.1 PTC 是什么、验证过什么收益
- **模式**：agent 不直接"调 MCP 工具把数据灌进上下文"，而是在 **Daytona 沙箱里写 Python、执行**，用 pandas 处理来自 MCP 服务器的金融数据、出图表、存工件；另有 Flash 模式（不启沙箱的快速问答）。仓库结构：`src/ptc_agent/`（Agent Core）、`docs/api/README.md`（PTC Agent API：workspace/run/SSE 流式）。
- **关键机制（作者自述 + 仓库结构佐证）**：workspace 初始化时**从 MCP schema 自动生成类型化 Python 模块**上传沙箱，agent 像 import 普通库一样用；prompt 里每个 server 只留**一行摘要**。作者数据：约 80 个工具横跨多 server，**prompt 成本与单 server 工具数量解耦**（3 个工具和 30 个工具成本相同）。[HN Show HN 作者原帖](https://news.ycombinator.com/item?id=47766370)
- **外部独立印证（重要，但非 benchmark）**：痛点被多方同行独立复现——Databento 官方 MCP 维护者："A year ago, I naively wrapped the API and certainly felt this pain. Having an API call drop a firehose of structured data into the context window was not very helpful"（其解法同为数据落 Parquet + DuckDB 查询）；sift-gateway（SQLite 存 payload + 暴露 python 查询工具）是社区自发的同构方案。→ 说明"代码执行而非数据直灌"是**通用 MCP 模式**（作者也明说不仅限金融）。[HN 讨论](https://news.ycombinator.com/item?id=47766370)
- **未验证的部分（关键诚实点）**：**没有任何公开量化 benchmark**。作者在 HN 亲口："We are building towards a benchmark as well. hope we can share quantitive metric soon"（2026-04-15）。token 节省数字是内部估算，外部无从复核。
- 配套工程：持久 workspace（`agent.md` + 文件索引每次 LLM 调用前重读）、progressive tool discovery（上下文放摘要 + 文档落盘 workspace）、Postgres 双池（应用数据 + LangGraph checkpoint）、Redis（SSE 事件缓冲 150K 事件 / 重连回放 / steering 队列）、多供应商模型层自动 failover、pgcrypto 加密 + 凭据泄漏检测脱敏。

### 3.2 被验证的价值点 vs 坑
**价值点**：问题定义准确（金融 MCP 工具的 schema 与数据量确实会击穿上下文窗口）；模式可泛化、社区共鸣强（HN 148 分 + 多个从业者背书同向方案）；"研究持久化"（workspace 化、agent.md 复合积累）是 Claude Code 式赛道里少见的金融翻译。

**坑**：
- **[高] 收益无量化公开验证**（作者自认 in progress）。
- **[中] 输出可信度无 validation layer**——HN 用户点名要求"至少要知道 20/30 个数据点算出的指标是对的，最好加 validation layer/可定制计算引擎，否则外行不知道指标错在哪"。
- **[中] 工程包袱重**：desktop/TUI/web 三端 + 沙箱依赖 Daytona，自托管需要 Postgres/Redis/Daytona 全套。
- **[低] 作者自己修过 LangChain DeepAgents 摘要 middleware 把压缩调用泄漏进 SSE 流成为可见 assistant 轮次的 bug**（修法：加独立 SSE event 类型；另做更准的 token 估算与 offloading）。
- **[低] 社区质疑声**："cool visuals" 非 "real results"（怀疑炒作）；`mhh__` 反驳 "mcp don't work"（认为 MCP 暴露 query endpoint 即可）；星数快照不一致（1.7k–2k，时间点不同）。

### 3.3 简历借鉴结论
**最该借**：① **PTC 模式本身**——"MCP 直灌 vs 沙箱写代码"的对比实验（量化 token 消耗 / 指标正确性）是当前 agent 工程最热方向之一，LangAlpha 给了现成的问题框架与论证；② **MCP schema → typed module 自动生成**（小而传播性强的点）；③ workspace 持久化（agent.md + 文件索引）思路。
**最不该借**：① 全栈三端 + 大规模基建（Postgres 双池 / Redis 事件缓冲 / Daytona）照抄——简历项目臃肿；② 依赖"Yahoo Finance 免费数据 + 零 API key"的数据链，会掩盖数据质量问题；③ 任何"帮用户赚钱 / vibe investing"的叙事——该讲"研究效率与 agent 架构"，软碰盈利。
