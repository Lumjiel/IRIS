# IRIS 前端 UI 设计规范（审美锚定执行标准）

> **本质**：ASCII 线框图只传达布局，传达不了"舒服感"。"好看/专业"不是形容词，是坐标。
> **方法**：参照物（坐标系）+ 写死规则（执行标准）+ 锚点验收（最小成本纠偏）+ 反模式（底线）。
> **原则**：实现时不需要审美判断，只需要执行规则。规则对了，结果不会差。

---

## 一、参照物（视觉坐标系）

| 区域 | 参照物 | 取什么 |
| ------ | -------- | -------- |
| 左栏数据卡 | **Stripe Dashboard** | 指标卡排版密度、数字字号层级、留白比例 |
| 时间线 | **Linear Issue 状态流** | 节点大小、连线粗细、完成态的克制感 |
| 报告正文 | **Notion / GitHub README** | 标题层级、段落间距、表格样式、阅读行宽 |
| 整体氛围 | **Perplexity.ai** | 浅色底、卡片阴影、信息密度适中 |

面试话术："视觉参照 Stripe + Linear + Perplexity 的设计语言"。

---

## 二、可执行规范（写死，不靠感觉）

```
间距系统：4px 网格，只允许 4/8/12/16/24/32/48
字号层级：24px(大数字) / 14px(正文) / 12px(标签)，三档封顶，禁止 10/11px
字重：标题 600 · 正文 400 · 强调 500，不用 bold(700)
颜色：slate 系打底；red-600/emerald-600 仅用于涨跌；accent 用 indigo-600
圆角：卡片 rounded-lg(8px) · 按钮 rounded-md(6px)
阴影：仅 shadow-sm，禁止 shadow-md 以上
边框：border-slate-200，禁止纯黑
数字：tabular-nums + 右对齐（金融数据必须等宽对齐）
动效：仅 transition-colors duration-200，禁止入场动画
字体：数字 JetBrains Mono（本地/npmmirror 引入，不依赖 Google）· 中文系统字体栈
```

**Tailwind 落地**：可固定为设计 token（`tailwind.config.js`），不散开硬编码。

## 三、锚点组件验收流程

**不要 7 个组件全做完再看效果。**

- 第 1 轮：做 `MarketDataCard`（数据可视化代表）+ 报告正文排版（长文阅读代表）→ 用户确认"行/不行"
- 第 2 轮：风格确认后批量铺开其余组件（时间线/TopBar/ActionBar/追问框）

为什么选这两个：MarketDataCard 考验「数据密度+数字排版+Sparkline」，报告正文考验「长文排版+表格+标题层级」。这两个过了，其余是降维。

## 四、反模式清单（实现时主动规避）

```
❌ 超过 3 种字号
❌ 卡片之间间距不一致
❌ 图标和文字没对齐（差 1px 就丑）
❌ 颜色超过 5 种
❌ 圆角混用（rounded / rounded-xl 混用）
❌ 阴影过重（像贴纸）
❌ 表格没有斑马纹或分割线
❌ 按钮样式不统一
❌ 空状态没处理（白屏）
❌ Loading 没有骨架屏（闪烁）
```

## 五、可视化专项规范

### Sparkline（行情迷你走势）

- 手写 SVG 折线：高度 32px、线宽 1.5px、颜色跟随涨跌（red-600/emerald-600）
- 无坐标轴、无网格 —— 参照 Stripe 指标卡迷你图，极简，不抢主数字焦点

### 时间线（研究进程）

- 竖向排列：节点 = 8px 圆点（完成=实心绿 · 进行中=脉冲蓝 · 等待=空心灰）
- 连线 1px `slate-200`
- **无图标、无卡片包裹、无进度百分比** —— 参照 Linear 状态流，越简单越专业
