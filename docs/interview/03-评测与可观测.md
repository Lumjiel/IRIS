### 1) 离线单元层
299 tests（2026-11-10，`pytest -q` 输出），含 16 条**故障注入**用例：注入数据源级故障，断言降级行为（`tests/test_fault_injection.py`）。

### 2) 端到端 Benchmark 层（真实数字，诚实口径）
`backend/eval/benchmark_run.py` 对样本股发起真实 SSE 研究请求，实测五指标：六章节完整率 / 来源标注率 / 端到端延迟 / token 成本（real 与 est 分开累计）/ Reviewer 一次通过率。

已实测 5 股（v2.1 复测，2026-11-08，`docs/benchmark.md`）：
- 修订快速通道上线后：延迟中位数 598.2s → 436.4s（-27.1%）
- 最优样本 600196：2508.8s → 543.7s（-78.3%），token 148.8K → 43.0K
- **也如实记录了回归**：000333 反向 +362%，根因已定位（修订=全文重写未消除，见 badcase Case 3）

样本池已扩到 **20 只**（代码注册于 `benchmark_run.py` `STOCKS`），15 只待真实 API 环境补数——表格不预填数字，原因见 `BLOCKED.md`（本夜环境 dummy key + 无外网）。

Token 口径（`docs/benchmark.md`）：invoke 路径用 provider 真实回传 usage；流式路径 provider 不回传，按中文 ≈1.6 chars/token 估算，**两者分开累计**（`app/utils/llm.py:21-28` 的 `_record_usage_real` / `_record_usage_estimated`），查询口 `GET /api/usage`。绝不把估算值冒充真实值。

## 可观测性

### 节点级 trace
每个图节点用 `@traceable(run_type="chain", name=...)` 包装（LangSmith 协议，`app/graph/graph.py:48-116`），同时 `emit_node_event(step, status, elapsed)` 把 start/done + 耗时推给 SSE 时间线——同一份事件既是云端 trace 又是前端实时进度，不做两套。

### SSE 流式与心跳
- ContextVar 持 per-request 队列，生产者线程跑同步 `llm.stream()`，消费者 async 推 SSE；`routes.py:425` 空闲超 15s 发 `: heartbeat` 防代理断连。
- 并行分支拿不到 ContextVar 的坑实测踩过：改为按 `thread_id` 显式注册表（`app/utils/streaming.py:47-63`）——这是「context 只沿 asyncio 任务继承链传播」的一手教训。
- 流式路径的额度降级与 invoke 路径对齐（403 → fallback 重试，`streaming.py:87-115`），回归测试 `tests/test_streaming.py::test_quota_error_triggers_fallback_stream`。

### 状态探测
`GET /api/status`（`routes.py:1161`）：探测当前实际数据层（`data_source` 即降级链落点）、`llm_degraded` 熔断状态、主备模型名，60s 缓存。`GET /api/usage`：进程级 token 用量。故障时**先看这两个端点再翻日志**。

### 会话记忆可观测
`conversation_summary` 每轮增量更新并随 checkpoint 持久化；`GET /api/memory/{thread_id}` 直接返回摘要、轮次、已搜索方向——planner 避让重复搜索的依据可在 API 层验证，不是黑盒。
