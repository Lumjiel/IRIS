## 测试分层的真实原则

- **外部依赖全 mock**：conftest.py 顶部 mock dashscope / tavily / sentence_transformers，测试不碰网络——本地与 CI 同绿的前提（badcase：见 [badcase-review.md Case 2](../badcase-review.md)）。
- **mock 被测逻辑 = 自欺**：故障注入测试 mock 的是**数据源**（akshare/httpx），断言的是**降级逻辑**本身（`tests/test_fault_injection.py`，16 用例）。
- **多源降级链的测法**：L1 挂 → 断言 L2 接住且 `degraded=false`；全链挂 → 断言 mock 兜底且 `degraded=true`、工具永不抛异常。这是「来源诚实」产品红线的测试化。

## Lint 门禁

```bash
ruff check app/ --select E9,F63,F7,F82   # All checks passed! rc=0（2026-11-10）
```
四类 = 语法错误(E9) / 无效比较(F63) / 不可达代码(F7) / 未定义变量(F82)。只卡「会炸的错」，不卡风格——风格争议不配挡 CI。

## CI（.github/workflows/test.yml）

- backend job：装依赖 → **ruff 四类** → `pytest --cov-fail-under=62`（环境变量全部 dummy key，证明测试离线可跑）
- frontend job：`npm ci && npm run build`
- 触发：push main / PR

## 部署事实

- 生产为另一台轻量服务器：裸机 uvicorn（`--workers 1`，RSS ~200MB）+ Nginx 容器反代 `/api` → `172.17.0.1:8081`，systemd 托管（证据：commit `1c7538e` 部署记录）。
- 单 worker 是内存约束下的选择：LangGraph + ChromaDB 常驻，横向多 worker 会让每个进程各持一份图与向量库。

## 红线（本仓库工程纪律）

不删测试、不 skip、不放宽断言修绿；不改 `[来源: ...]` 标注逻辑；密钥不进代码；`.env` 不入库。这些写在 `AGENTS.md`，由 CI 与 review 双重把关。
